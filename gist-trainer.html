Step 2

Words become rows of numbers

A language model cannot read letters. Before anything happens, text is chopped into pieces (usually a word or part of a word; we will call each piece a token), and each token is looked up in a table. The table has one row per token, and each row is a list of numbers. That row is the only thing the model ever sees for that token.

A real model's rows are a few thousand numbers long. Our toy uses three numbers per row, so every row fits on a line and can be painted as a colour (first number → red, second → green, third → blue). The colour is just a way to see a row at a glance; the numbers are what matter.

Step 3

What a long prompt costs

A system prompt is a block of instructions placed in front of every conversation. In our toy it is eight tokens long. In Shopify's agent it was about 6,000.

Two costs come from it. First, the model must work through every prompt token before it can produce the first word of its reply. Second, and less obvious, for every word it writes it looks back across everything in front of it, prompt included. So a 6,000-token prompt is not paid once per request; it is re-scanned once per reply word.

The toy prompt, as the model sees it

Then the user's question (e.g. price?), then the reply, one token at a time. Each reply token looks back across all 8 prompt tokens plus the question.

Gisting's bet is that most of those 6,000 rows are carrying very little each: grammar, connective words, repetition. If you could hand the model 1,500 rows that together carry the same instruction, both costs shrink by the same factor.

Step 4

Add blank rows to the table

Nothing says the table may only contain real words. We can append rows for tokens that do not exist in any language. Decide how many: Shopify chose a 4-to-1 squeeze, so 6,000 prompt tokens become 1,500 gist tokens. In the toy, 8 prompt tokens become 2 gist tokens.

At this moment the new rows are just names, <gist_0> and <gist_1>, with no numbers in them. They mean nothing yet. The entire training process that follows exists to fill in these six numbers.

Step 5

Pick their starting numbers

Training works by starting from some numbers and improving them. The obvious start is random numbers. Shopify found a far better one: cut the prompt into consecutive chunks (four tokens each for a 4-to-1 squeeze), and set each gist row to the average of the rows in its chunk. Gist row 0 starts as a blurred blend of prompt tokens 1–4; gist row 1 of tokens 5–8.

Try both. The "starting mismatch" number is explained fully in step 7; for now, lower is better and 0 would be perfect.

Why it helps. Shopify saw their starting error fall by a factor of about 7 with averaged starts. The averaged rows already sit "near" the prompt tokens they replace, so training starts most of the way to the finish rather than from nowhere. The toy shows the same effect with its own ratio.
Step 6

Teacher pass: run the model with the real prompt

Now we need a target to aim for. Take one logged conversation, put the real prompt in front, and run the model. What comes out is not a word; it is a list of odds, one per candidate word, for what the next word should be. Save that list. It is the behaviour we are trying to preserve. We call this run the teacher, but note: it is the ordinary model doing its ordinary job.

To make the arithmetic visible, our toy model is a three-line recipe. A real model is the same idea repeated through dozens of layers with billions of numbers, but nothing conceptually different happens.

Step 7

Student pass and the mismatch score

Run the identical model again on the identical question, with one change: the eight prompt rows are swapped for the two gist rows. This run is the student. Same weights, same recipe, different thing in front.

Now compare the two lists of odds. We need a single number that says "how far apart are these", so that "improve" has a meaning. The one Shopify uses (its technical name is KL divergence) works like this: for each candidate word, take the teacher's odds and multiply by how much more the teacher believes in that word than the student does (measured on a log scale, so that halving belief counts the same as halving it again). Add up over all words. If the two lists are identical, every term is zero. The more the student under-rates words the teacher likes, the bigger it grows.

Why average over several questions? The gist rows must work for every conversation the prompt would have handled, not one. So the score we actually train on is the average mismatch across a large, varied set of logged conversations. Shopify's last big gain came from making that set bigger and more varied. The toy uses three questions.
Step 8

Find the slopes and nudge

We have six numbers we are allowed to change (two gist rows × three numbers) and one score we want to lower. For each of the six, ask a simple question: if I raised this number by a hair, would the score go down or up? The toy answers it literally: raise the number a tiny bit, recompute the score; lower it a tiny bit, recompute; the difference, divided by the size of the hair, is that number's slope. A negative slope means "raising this lowers the score".

Then move every number a small step against its slope, all six at once. That is one training step. Repeat. The score falls, quickly at first, then flattens as the student converges on the teacher.

Everything in the model that is not a gist number is left untouched. That is what "the weights are frozen" means: the model's own billions of numbers also have slopes, but we ignore them and move only the six.

Step 9

Ship the rows

When the score stops falling, stop. The gist rows are final. Two small edits make them live: append the rows to the model's table permanently, and tell the tokenizer (the text-chopper) that <gist_0> and <gist_1> are real tokens now. From then on, every request begins with those two tokens instead of the eight-word prompt. The serving software treats a gist token exactly the way it treats the: look up its row, feed it in. No special code anywhere.

Step 10

Toy vs. real: what scales, and what the toy hides

Numbers being trained61,500 × a few thousand
Model recipe3 lines, one layerdozens of layers; the gist rows must work at every one

How slopes are foundnudge each number, re-scorebackpropagation: all slopes in one pass (same answer, vastly faster)
Time per full runinstant30 h → 6 h after saving the teacher's lists once and reusing them

Two things the toy hides. First, the model has many layers, and the gist rows only enter at the bottom; training has to find rows whose effect, after passing through every layer, matches the prompt's. That is why it takes hours, not seconds. Second, when averaging the score over many conversations, how you average matters. Averaging each reply's tokens first and then averaging replies down-weights every token in a long reply; Shopify found this made the student hallucinate. Averaging over all tokens in the batch at once kept long replies at full weight and produced stable rows.

What the toy shows faithfully. The frozen model. The two passes. The one score. Slopes that come from the score alone. Averaged starts beating random starts. And the ending: the deliverable is rows in a table, nothing else.

Reference

Plain-words glossary

Token
A piece of text the model treats as one unit: usually a word or part of a word, sometimes punctuation. Text is chopped into tokens before the model sees it.
Row / embedding
The list of numbers the table holds for a token. "Embedding" is the technical name; on this page it is just "the token's row".
System prompt
A fixed block of instructions placed in front of every conversation, invisible to the user, telling the model how to behave.
Gist token
A made-up token added to the table whose row is trained so that a handful of them, placed in front, make the model behave as if the whole system prompt were there.
Teacher
The model run with the real prompt in front. Its list of next-word odds is the target.
Student
The same model run with the gist tokens in front. Its list is what we want to match to the teacher's.
Distillation
Any training that copies one run's outputs rather than learning from labelled right answers. "Self-distillation" means teacher and student are the same model.
KL divergence / mismatch score
A single number measuring how far one list of odds is from another. Zero means identical. It grows fastest when the student gives low odds to words the teacher gives high odds to.
Slope
For one adjustable number: how much the score changes if that number is raised by a hair. Its sign says which way to move; its size says how much that number matters right now. "Gradient" is the technical name for the full set of slopes.
Frozen weights
The model's own numbers are left exactly as they are during training; only the gist rows move.
Backpropagation
A way of computing every slope at once from a single pass, instead of re-scoring after nudging each number individually. Same answer as the toy's method, enormously faster.
Tokenizer
The text-chopper: the component that turns text into tokens and knows which tokens exist.
Batch
The set of conversations whose mismatch scores are averaged together for one training step.
